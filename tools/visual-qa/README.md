# 角色与 UI 视觉校对

此工具调用当前 `game/renderer.js` 和真实角色资源，不加载替代骨骼或截图充数。动态校对页展示六种植物、五种僵尸，可切换攻击、命中、伤残、退场、特殊动作、原版角色与剧情画风，并暂停定格。下方草坪对照直接采样与960×576的经典柔和采样。

在仓库根目录执行：

```powershell
node tools/build-visual-qa.cjs
python -m http.server 8793 --bind 127.0.0.1
```

- 角色页：`http://127.0.0.1:8793/tools/visual-qa/index.html`
- UI临时场景：`http://127.0.0.1:8793/tools/visual-qa/ui-cases.html`

UI临时场景从生产index生成，只在内存中提供第二章2-3的五卡进度，页面底部有明确标识；不读取、写入、清除真实冒险存档。生成的HTML由Git忽略，避免维护一份过期游戏模板。

此工具用于开发视觉核查，不加入游戏运行目录，也不自动打包或发布。截图和关键帧只能证明对应姿态；连续动作、前后衔接与实际尺寸仍需目视确认，不能用单元测试替代。

行列校对支持五行十列格线、落脚线、当前2-3阵型与经过墓碑列三种场景；草坪直接调用生产背景与角色绘制，切换格线不影响正式游戏。首行与中行的对空仙人掌、气球悬浮/落地用于核对高姿态和遮挡。

新增“墓碑前近身 / 高姿态”站位，集中查看首行、中行、底行高仙人掌与僵尸、墓碑的深度关系。“实战衔接 · 对空退场”在0–1秒保持活体对空姿态，1秒触发真实engine击败事件；可定格0.9、1、1.15、1.3、1.5秒查看连续变化。单体预览同一角色各状态保持固定位置和比例，避免预览自身缩放掩盖跳位。开发测试以重复RAF验证死亡来源不会因复用样本遗留deathRecorded而丢失；实际视觉仍以浏览器画面为准。

# 水路与屋顶：让地形决定接应方式

本轮交付四张地图的设计数据，供地图册与场地视觉试演读取。它们的状态全部为 `design`，没有加入当前七关可玩营救关卡。现有关卡“屋顶囚室”的名字，也不代表坡面、花盆与原版屋顶弹道已经实现。

数据源：[battle-map-water-roof.js](../game/battle-map-water-roof.js)。以该文件的坐标、规则和制作前置项为准。

## 保持的共同战斗约定

- 当前场地为五行十列。这是营救模式的五行水路变体，不能称为经典原版六行泳池已经复原。
- 最后一列（零基第9列）始终是五段独立栅栏，各600耐久；营地为零基第2行、第8列。博士开局由玩家指定藏身行，承受10次有效命中，人机不读取、不猜测该位置。
- 三支队伍，每支最多三人；60秒准备可提前结束。玩家调遣没有冷却，植物按阳光、卡片冷却和当前既有准备阶段契约部署。
- 植物实体允许慢速沿列换行，每格至少3秒；移动中只沿当前行按各自经典身份攻击。豌豆不获得全局追踪，大嘴花不变成远程单位，倭瓜仍预备后一次跳砸。
- 路线补给碑仍是接应和补给对象，不用故意献祭同胞产生物资。五段栅栏、博士计数和路线补给失败契约沿用，不因换地图自动重置战斗中损失。
- 阅读信件、门口对话与战后故事均暂停行动计时。夜色、水面、坡面不会替代明确的落点、可走范围和人物脚底标记。

## 坐标及通路

以下坐标全部零基，行0–4、列0–9。中心篱墙位于列5，仅在各图指定缺口开放；第9列不放门、货物、会合点或补给碑。

### 货场蓄水池 · 栈道交接（3-3）

水行是1、2，桥面成对放在列2、4、6、8。换行通道也为列2、4、6、8；地面队只在桥面跨越水行。中心缺口在行0、4，北岸和南岸都可在救出任何新角色前走通。两间房门分别在(0,1)、(4,1)，会合点在(3,4)，前进碑(0,7)、整备碑(3,7)。

一队走北岸，二队走南岸，三队守东岸。巨人认出的脚印属于这场新获救的小鬼，与灯房写信等老周的小鬼不同。战斗来自先后接人和桥口换班，而非提高敌方血量。桥面固定且不会坍塌，不用隐藏倒计时惩罚阅读与思考；气球的飞越不能替地面护送对象判胜。第一版只在岸上种植，睡莲、水生植物、水生僵尸完成后再开放水中布阵。

4-1回到同一蓄水池泵站取护板与泵轮：阿汀是照料设备的修理工，不是又一位被捕旧同伴。先修好住户取水管，再用公开载重的检修浮台分批交付零件。需要另接浮台和载重规则，不能用3-3护送脚本更名冒充打捞。

### 旧运河 · 石桥开路（3-2）

水行只有2，固定桥在列2、6、8；中心缺口在行0、3。巨人囚场(1,1)，搬运木料(0,3)、住户接应点(4,3)，石桥接手平台(3,2)，东岸两碑(0,7)、(3,7)。普通队沿北岸长旁道先救巨人，获救后搬开指定木料形成较安全返程。固定桥和长旁道都不会因搬运失败关闭。

4-2在4-1组件回收后复用这条运河运输零件驳船。矿工核桥下净空、巨人装船，岸上队伍逐段开闸；未安全时船停在公开停靠点等待，不在读信时自动漂进火线。落水检修员可以先接回，组件必须实际交付到地下工坊卸货坡。驳船实体、停靠、水闸与货物状态需单独实现。

### 旧街屋顶 · 风里的吊篮（4-4）

中心缺口在行1、3，烟囱占(0,3)、(4,3)。信标和散热器组件在(0,1)、(4,1)，屋脊校准台(2,4)，前进碑(1,7)、整备碑(3,7)，起吊交接台(3,3)。巨人在稳固平台架吊篮，送药人带路，阿铆从外圈伤员接应线回队换班。

2-2上首次使用此屋顶场地，任务是救出送药人和药袋；4-4再次沿同一维修竖井上来，任务变为货物起吊。人物状态和任务不同，不添加一场重复的送药人营救。第五章调度站也可用屋顶模板，但它是有限补给截断任务，不沿用4-4吊篮目标。

视觉上必须让坡面高度同时影响脚底、阴影、受击和点击坐标。直射会与坡面相交，抛射按弧线越坡；花盆是可识别底座，换行时与植物一起转移，不出现身体漂浮、脚底断裂或移植中免费落种。烟囱和高仙人掌按脚底深度排序，护送标识放在可读的前景层。

### 夜间屋顶 · 第二盏灯（4-5）

中心缺口在行0、2、4，烟囱占(1,3)、(3,3)。冰弹漏水管测试口(0,1)、火弹冰封闸测试口(4,1)，屋脊校准灯(2,4)，北南信标(0,6)、(4,6)，试车整备碑(2,7)。

4-3已恢复工坊供电，4-4已运好信标与散热组件，4-5才接通信标并试车。冰弹冻住漏水管形成通过窗口，火弹融开冰封闸口，踩压先预警完整落区，支援舱只投放已获救队伍。接应同胞先进入安全区，试车可以中止，信标损坏暂停后续步骤但不抹掉已通过项目。

角色轮廓、栅栏计数、倭瓜起跳和射击轨迹始终可辨认。默认经典巨大机甲，文化版本共用判定，不让小鬼成为消耗弹药。此处完成对终战能力的教学，再接第五章撤离与后院决战；3-4最后路灯仍是前一章的夜间货场撤离，不在这里重复。

## 原生资源观察与视觉实施建议

已检查当前文件树：`game/assets/images/background1.jpg`、`background2.jpg`存在；图鉴另有 `assets/ui/almanac/Almanac_GroundPool.jpg`、`Almanac_GroundRoof.jpg`、`Almanac_GroundNight.jpg`。图鉴地面是小型介绍素材，不能把它们直接放大成完整泳池或屋顶战场。

水相关拆件已有 `Zombie_duckytube_inwater.png`、`Zombie_whitewater1–3.png`、`Zombie_snorkle_whitewater1–3.png`；这只证明素材在，不证明水生碰撞、游泳动作组合与水下遮挡已接入。睡莲已有图鉴图 `assets/almanac/lily.webp`，同样不能代替底座实体实现。

本轮另一位地图 agent 正在从用户本地 `main.pak` 提取原版 `background3–6.jpg` 与雾素材。优先复用这些完整场地的纹理和边界，统一在现有格点上试演角色；保留其原生纸牌、木框与柔和低清质感，不用新画的高饱和扁平色块覆盖整个战场。泳池六行原生背景适配五行时必须重做水岸与桥面的坐标映射，不能按贴图的视觉位置直接假定碰撞也对齐。

原版屋顶有真实斜坡，画面裁切应先锁定角色脚底与点选范围再定背景偏移。夜屋顶可由原版屋顶地形配合独立夜色与灯光处理，但需要明确标成新的场地变体，不能称为原版独立夜屋顶关卡复原。

## 实施门槛与验证

1. 地图册阶段：四图均标记设计中；用生产角色显示实际场地比例、墓碑、栅栏和博士遮挡，不能把静态演示称作可玩新关。
2. 固定桥水路：接入水域通行与桥面碰撞，证明未解锁水生单位时两处房门都能往返。之后实现双护送交接。
3. 屋顶：共享高度坐标、花盆、坡面弹道与烟囱碰撞，检查高仙人掌、气球、倒地角色和护送标识的遮挡。
4. 水闸和夜间试车：独立驳船与货物、交付记录、灯坏重接、冰火窗口、安全区和可中止步骤；重开、读信暂停、失败后恢复都不能重复发奖或丢目标。
5. 全程保留人机仅观察公开状态的边界；不同博士藏身行不应改变同一随机种子下的初始植物部署。

本轮没有调整敌方数值、开放新关卡、打包或远端发布。坡度、载重、窗口时长与试车参数尚待实现和平衡，不能当作已验收的最终参数。
